# Travel Plan Markdown Contract

本文件定义完整旅行计划的固定 Markdown 输出协议。

## 1. 核心规则

完整旅行计划的核心标题属于稳定 Contract：

- 标题名称不得修改
- 不得用同义标题替代
- 不得添加 Emoji
- 不得改变标题层级
- 不得把两个核心模块合并

内容可以灵活，核心结构必须稳定。

## 2. 标准结构

```markdown
# {目的地}{天数}旅行计划

## 行程概览

- 日期 / 天数：
- 旅行者：
- 旅行风格：
- 核心路线：
- 预算定位：

## 行前准备

- 大交通：
- 天气：
- 住宿区域：
- 当地交通：
- 预约事项：
- 必备物品：

## Day 1｜{主题 / 区域}

### 上午

...

### 下午

...

### 晚上

...

### 交通

...

### 费用

...

### 提醒

...

## Day 2｜{主题 / 区域}

...

## 住宿建议

...

## 美食建议

...

## 预算参考

...

## 出行提醒

...
```

## 3. 固定标题

必须使用：

```markdown
## 行程概览
## 行前准备
## 住宿建议
## 美食建议
## 预算参考
## 出行提醒
```

不得使用同义标题替代，不得添加 Emoji。

例如：

```markdown
## 📌 行前准备
```

不能替代：

```markdown
## 行前准备
```

例如：

```markdown
## 整体安排
```

不能替代：

```markdown
## 行程概览
```

## 4. 行程概览固定字段

```markdown
- 日期 / 天数：
- 旅行者：
- 旅行风格：
- 核心路线：
- 预算定位：
```

信息未知时可以写“未特别限制”、合理概括或必要假设，但不得编造用户个人信息。

## 5. 每日标题

每一天必须使用：

```markdown
## Day N｜主题 / 区域
```

例如：

```markdown
## Day 1｜龙门石窟 · 洛阳博物馆
## Day 2｜老城文化线
## Day 3｜白马寺 · 返程
```

普通行程优先使用：

```markdown
### 上午
### 下午
### 晚上
```

根据真实情况也允许 `### 清晨`、`### 全天`、`### 夜间`。

每个完整 Day 应包含：

```markdown
### 交通
### 费用
### 提醒
```

## 6. 币种规范

所有金额必须明确币种。不得仅用 "¥" 表示金额——对中文用户，"¥" 容易被误读为人民币（CNY），而实际往往是当地货币（如日元 JPY）。

原则：当地货币是事实价格，人民币等只是换算参考。

- 事实价格一律用当地货币表达（如 JPY / THB / USD / EUR / KRW），书写为「JPY 14,000」或「14,000 日元」，不要用裸符号 "¥"。
- 人民币换算金额只能由 Main 调用 `convert_currency` 基于当前参考汇率换算得出；不得编造汇率，不得把换算价与事实价混写。
- 同一预算模块内币种表达保持一致。
- 预算模块开头可先声明一次币种基准，例如：以下金额均为日元（JPY），人民币仅作辅助参考。

如提供双币表达，同一预算模块必须使用同一条 `convert_currency` 汇率：

- 14,000 日元/人（约人民币 680 元）

没有可靠汇率时，可退化为仅当地货币：

- 14,000 日元/人
- JPY 14,000/人

人民币换算金额由 Main 调用 `convert_currency` 得出；示例中的「680 元」仅作格式演示，不得照搬、不得编造汇率。汇率服务不可用时，仅输出当地货币。

## 7. 模块职责

### 行前准备

写出发前需要知道和准备的内容，如大交通、天气 / 气候、住宿区域、当地交通、预约、证件、衣物、防晒雨具等。

### 住宿建议

优先推荐区域、商圈、地铁站附近及选择理由；没有可靠依据时，不编造具体酒店。

### 美食建议

推荐当地代表美食、用餐区域和与每日路线结合的餐饮建议；没有可靠依据时，不编造具体餐厅事实。

### 预算参考

按大交通、住宿、当地交通、门票、餐饮、体验等估算；若用户有明确预算，应说明方案是否大致符合。
最终预算必须基于最终实际采用的路线与方案计算，不得混用未采用备选方案的价格。
存在多项费用时，最终总额 / 人均总额优先采用 `calculate_budget` 的确定性计算结果，不自行重新心算。
所有金额遵守「币种规范」（第 6 节）：以当地货币表达事实价格，人民币仅作换算参考，不得用裸 "¥"。

### 出行提醒

写整趟旅行过程中持续需要注意的预约、天气变化、证件、支付、行李、客流、景区规则、安全等事项，不要与行前准备大量重复。

## 8. 特殊旅行类型

允许增加额外模块，例如：

```markdown
## 自驾路线建议
## 雪场与装备
## 登船与岸上观光
## 亲子注意事项
```

额外模块只能补充，不能替代核心模块。

## 9. 输出前检查

发送完整计划前确认至少存在：

```text
# {目的地}{天数}旅行计划
## 行程概览
## 行前准备
## Day 1｜...
## 住宿建议
## 美食建议
## 预算参考
## 出行提醒
```

多日旅行的 Day 数量必须与旅行天数一致。

所有金额币种明确、遵守第 6 节「币种规范」，预算模块不得出现裸 "¥"。

Markdown Contract 的稳定性属于完整旅行计划正确性的一部分。
