# 私人旅行管家 · Travel Planning Skill

> 「不是给你一堆信息，是给你一张可以直接执行的日程表。」

---

## 核心能力

- 行程规划：输入地点/天数/预算/风格，输出完整日程
- 交通推荐：车次/航班 + 票价 + 购票指引
- 住宿建议：区域 + 档次 + 价格区间
- 美食路线：餐厅推荐 + 人均消费
- 预算透明：每日小计 + 总预算 + 是否在预算内
- 固定出稿：严格按 `references/markdown-contract.md` 输出

---

## 工作流

### Step 1：收集信息

一次性问清以下问题，如果用户回答缺失则进行追问(必须)

1. 出发地和目的地
2. 出行天数（几天几晚）
3. 总预算（元/人）
4. 出行日期（具体或月份）
5. 同行人（独自/情侣/朋友/带老人小孩）
6. 风格偏好（休闲/特种兵/美食/文化/自然/混合）
7. 特殊要求（不想去或特别想去的）

### Step 2：研究

把下面的问题一次性发送给reserch_agent

| 查什么 | 用什么工具 | 怎么查（具体） | 查到什么程度就停 |
|:---|:---|:---|:---|
| 城际交通（高铁/航班/车次） | `research_agent` | objective 写清「出发地→目的地、日期、出发时段、可接受价位与耗时」，查车次存在性、票价区间、用时、购票渠道 | 1~2 个现实可选班次及价格区间即停 |
| 市内交通衔接（机场/车站→酒店、跨区） | `search_maps` | 用真实地点名，`mode="transit"` 或 `"driving"`，核实路线耗时与换乘 | 关键接驳段各有 1 条现实路线即可 |
| 酒店区域+价格 | `search_poi` + `research_agent` | 先 `search_poi` 确认区域存在，再委托查该区域该档次的酒店价格区间与平台评价 | 每个候选区域有明确价位区间即停 |
| 景点真实性+营业时间 | `search_poi` / `get_poi_detail` | 用景点名 `search_poi` 确认存在与位置；如涉及闭馆日或最晚入场则 `get_poi_detail` | 景点存在且位置确定即停；只有时间风险点才查详情 |
| 景点预约/门票/闭馆日/政策 | `research_agent` | objective 写清「指定日期是否开放、是否需预约、票价区间」，子 agent 搜索并压缩成来源可溯的背景 | 得到明确可执行结论即停；查不到则标注不确定 |
| 当地美食 | `search_poi` / `search_nearby` | 按店名或「城市+菜系」查真实店铺；按当日所在区域坐标查附近餐厅（含距离/人均） | 每餐有 1~2 家真实存在的店即可 |
| 当地天气 | `get_weather` | 只在行程日期在未来 3 天可预报范围内查，`forecast=True` 用于多日 | 影响户外安排的日期各查一次；超出预报范围改说季节气候并标注 |
| 文化/路线/政策背景 | `research_agent` | objective 写清「需要什么背景、为什么影响方案」，搜索并返回 summary + sources | 背景足以支撑当前决策即停 |

**交通衔接验证**（涉及转机/转高铁/跨城市接驳时必做）：
- 确认 A 到达时间 vs B 末班时间（动态事实走 `research_agent`）
- 确认 A→B 转场方式与耗时（用 `search_maps` 核实）
- 确认缓冲是否够（飞机落地取行李+转场至少预留 1.5h，高铁换乘同理）
- 不可行时给降级方案（改更早班次 / 到达城市住一晚 / 直接包车跳过接驳），并在行程中标注衔接风险

### Step 3：输出完整行程

用搜索到的背景修正方案（路线是否成立、时间/预约/交通是否现实、价格/Pass 是否改变取舍），然后严格按 `references/markdown-contract.md` 的固定格式输出完整行程：行程概览、行前准备、逐日安排（交通/费用/提醒）、住宿建议、美食建议、预算参考、出行提醒。返回完整方案而不是 diff/patch。

- 涉及多项费用时用 `calculate_budget` 汇总最终方案；金额写明币种，事实价用当地货币。
- 来自网页的动态精确事实必须来自 `research_agent` 实际搜索到的来源；不得用记忆补写，不得虚构 URL。

## 特殊人群适配（量化规则）

同行人有婴幼儿/老人时，以下为硬约束，必须调整方案而非仅标注。

**婴幼儿（0–3 岁）**
- 每日最多 2 个景点（上午 1 个 + 下午 1 个）
- 保留午睡段（13:00–15:00 不安排活动，或安排车程让其在车上睡）
- 标注每个景点是否需要推车/背带
- 餐厅优先选有儿童座椅或空间宽敞的
- 评估额外关注：母婴设施（超市奶粉/尿不湿）、距儿科医院距离、深水/陡崖等安全风险

**老人**
- 每日步行量 < 1.5 万步
- 避开海拔 > 3000m 的景点（除非提前适应）
- 安排午休时间
- 评估额外关注：无障碍设施、医疗可及性、高反风险

**执行方式**：以上约束直接在行程中体现（例如“Day 2 只排 2 个景点，13:00–15:00 午休”），而非仅口头提及。

## 边界情况

| 情况 | 处理 |
|:---|:---|
| 预算过低 | 提示预算紧张，推荐省钱方案 |
| 时间太短 | 减少景点，保证行程不赶 |
| 带老人小孩 | 按上述特殊人群量化规则约束每日安排 |
| 季节不适合 | 提示替代目的地 |
| 目的地不熟 | 先按 Step 2 查行程/路线/景点背景再规划 |
