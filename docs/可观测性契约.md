# 可观测性契约

> 目标：一次用户问题可以从业务 request 一直追到 Agent、LLM、Tool、DB 与平台故障。

# 1. 四个观测面

```text
OpenTelemetry
→ 基础设施 span 标准协议 / instrumentation（不建设独立平台）

LangSmith
→ Agent semantic trace / AI eval

LiteLLM telemetry
→ model/provider/retry/fallback/cost

现有平台监控（非独立 Trace 平台）
→ HTTP/SSE/DB/Redis/CPU/Memory/alerts
```

# 2. ID 体系

```text
request_id
→ Travel Agent business request

trace_id / span_id
→ OpenTelemetry

litellm_call_id
→ LiteLLM real model call
```

不要自建第二套 `trace_id = uuid4()`。

# 3. OTel Root

FastAPI、SQLAlchemy、Redis 等基础设施按需接入标准 OTel instrumentation；是否导出由现有平台决定，不单独建设 OTel 平台。

业务 metadata 可关联：

- request_id；
- route；
- authenticated user hash / internal id（按隐私策略）；
- conversation_id（必要时）；
- request status。

# 4. LangSmith

至少观察：

- Main；
- Researcher；
- Tool calls；
- model calls；
- latency；
- exceptions；
- trajectory。

Prompt / Response 是否上传由 `安全与数据治理.md` 决定。

# 5. LiteLLM

至少观察：

- logical model；
- actual provider/model/deployment；
- latency；
- retry；
- fallback；
- cooldown / health；
- 429 / 5xx；
- usage；
- response cost；
- call id。

# 6. API / Platform Metrics

至少：

```text
http_requests_total
http_request_duration
http_4xx / 5xx

active_sse
sse_disconnect
request_deadline_exceeded

db_pool_usage
db_query_latency
db_errors

redis_latency
redis_errors

tool_latency
tool_errors
tool_degradation
```

# 7. Logs

Structured logs。

至少字段：

```text
timestamp
level
service
request_id
trace_id
event
error_code
```

不要在普通日志输出：

- full Authorization；
- API Key；
- Provider Secret；
- raw passport / credentials；
- 未经数据策略允许的完整 prompt/response。

# 8. Alerting

P0 需要可操作告警：

- 5xx spike；
- deadline exceeded spike；
- LiteLLM unavailable；
- provider fallback/cooldown anomaly；
- DB unavailable / pool saturation；
- Redis unavailable；
- critical Tool unavailable；
- cost spike；
- cross-user access security event。

# 9. Business Usage Attribution

业务 cost 统计来自 `business_llm_usage`。

LiteLLM 负责 cost source，业务表负责产品归因。

# 10. Trace Failure

Observability 平台不可用不能默认阻断所有用户请求。

Tracing/logging failure 需要：

- 最小降级；
- 本地/platform error metric；
- 不无限 retry 导致主链路阻塞。

# 11. Data Policy

采集什么必须与 `安全与数据治理.md` 一致。

Observability 不是无限保存用户内容的理由。
