# DeepSeek Travel Agent A/B 实验报告 v1

## 1. 实验目的

本实验用于验证：

1. 通用大模型是否已经具备旅行规划能力。
2. 联网搜索是否显著提升旅行规划质量。
3. Travel Agent 产品真正需要优化的是搜索能力，还是决策能力。

实验不用于评估最终产品架构，而用于建立 baseline。

---

# 2. Golden User Request

测试输入：

> 郑州出发，北京 3 日游，8 月 26 日出发，2 人情侣，总预算 5000 元，希望经典打卡、体验好、不想太赶。

约束：

- 出发地：郑州
- 目的地：北京
- 时间：3天
- 人数：2人情侣
- 预算：5000元
- 目标：经典体验 + 舒适节奏

---

# 3. A/B 实验一：旧自由 Research Agent vs Bounded Research

## A：当前 bounded research 架构

特点：

- Planner 固定生成研究计划
- Research actions 有限制
- Finalizer 汇总结果
- 有明确边界

结果：

| 指标 | 数据 |
|-|-|
| 结果 | 成功 |
| 耗时 | 165.5秒 |
| 模型调用 | 12次 |
| 工具调用 | 27次 |
| 总tokens | 196125 |
| 来源URL | 46 |

输出：

成功生成完整北京3日游方案。

---

## B：旧自由迭代 Research Agent

特点：

- 自由决定搜索
- 自由迭代
- 没有严格研究边界

结果：

| 指标 | 数据 |
|-|-|
| 结果 | 失败 |
| 耗时 | 133秒 |
| 模型调用 | 11次 |
| 最终输出 | 校验失败 |

错误：

Exceeded maximum output retries。

---

## 实验结论

bounded research 明显优于自由迭代 research。

原因：

不是搜索能力更强，而是：

- 限制探索空间
- 保证结构化输出
- 控制 Agent 收敛路径

因此 Research Agent 应该是 bounded decision verification，而不是自由搜索 Agent。

# 4. 实验二：DeepSeek V4 Flash 无联网 vs 官方 Web Search

## B0：DeepSeek V4 Flash 无联网

配置：

- deepseek-v4-flash
- thinking disabled
- 无工具

结果：

| 指标 | 数据 |
|-|-|
| 耗时 | 18.8秒 |
| 输入tokens | 211 |
| 输出tokens | 1854 |
| 搜索 | 0 |

能力：

模型可以完成：

- 用户需求理解
- 行程设计
- 预算估算
- 节奏安排

不足：

- 动态事实可能错误
- 预约规则无法保证
- 缺少现实验证

---

## B1：DeepSeek V4 Flash + 官方 Web Search

配置：

- deepseek-v4-flash

结果：

| 指标 | 数据 |
|-|-|
| 耗时 | 29.5秒 |
| 搜索次数 | 6次 |
| 来源 | 47+ |
| 输入tokens | 43930 |

# 5. Web Search 实验结论

## 结论1：联网不是旅行规划核心能力

B1 搜索大量信息，但是最终方案提升有限。

搜索解决：

- 当前事实
- 动态信息
- 来源验证

搜索不能自动解决：

- 用户真正想要什么
- 哪些景点价值最高
- 如何安排体验节奏

---

## 结论2：自由搜索存在严重成本问题

问题：

LLM 会：

- 搜很多
- 收集很多
- 消耗大量上下文

但是大量信息不会改变最终决策。

因此：

不能采用：

用户输入 → 搜索 → 规划

# 7. 对 Research Agent 的重新定义

Research Agent 不应该是：

> 帮我研究北京旅游

应该是：

> 验证会改变旅行决策的不确定变量。

例如：

错误：

研究八达岭长城

正确：

验证八达岭是否适合第三天返程日：

- 往返耗时
- 开放情况
- 门票
- 交通风险

---

# 8. 最终实验结论

当前 Travel Agent 的核心竞争力不是：

- 搜索更多
- 使用更多工具
- 创建更多 Agent

而是：

> 理解用户旅行目标，并选择真正影响决策的信息进行验证。

后续架构设计应围绕：

1. Trip Context Model
2. Decision Gap Analyzer
3. Research Router
4. Reality Layer

展开。

# 9. 模型实际输出记录

本章节保留 A/B 实验的原始模型输出摘要，用于后续产品评审和架构决策。

## B0 原始输出摘要：DeepSeek V4 Flash 无联网

模型生成结果特点：

- 能理解“郑州出发、北京3日、情侣、5000预算”的基本约束。
- 自动生成完整 Day1-Day3 行程。
- 能安排住宿区域、交通方式、预算范围。

典型路线倾向：

```
Day1:
天安门 / 故宫 / 景山 / 前门

Day2:
颐和园 / 圆明园 / 胡同区域

Day3:
天坛 / 前门 / 城市休闲
```

优点：

- 行程节奏自然。
- 能考虑情侣体验。
- 不依赖外部信息即可完成候选方案。

问题：

1. 动态事实无法保证。

例如：

- 高铁具体车次
- 当前预约规则
- 门票政策

可能基于历史记忆生成。

2. 旅游价值排序不足。

例如第一次北京用户，模型可能优先选择颐和园、圆明园，而没有主动把八达岭长城作为核心体验。

结论：

B0 证明通用 LLM 已具备候选规划能力，但缺少现实世界验证能力。

---

## B1 原始输出摘要：DeepSeek V4 Flash + 官方 Web Search

模型行为：

- 主动触发 Web Search。
- 搜索高铁、景点、预约等信息。
- 引入大量来源。

搜索行为：

```
web_search: 6次
sources: 47+
```

最终方案与 B0 相近：

```
Day1:
天安门 + 故宫 + 景山

Day2:
颐和园 + 什刹海

Day3:
天坛 + 前门
```

优点：

- 动态事实可信度提高。
- 能找到当前规则和价格信息。

问题：

1. 搜索成本巨大。

```
input tokens:
211
↓
43930
```

2. 大量搜索结果没有改变最终路线。

3. 搜索没有自动提升旅行决策质量。

结论：

联网应该用于验证关键决策变量，而不是让模型自由探索所有旅游信息。

---

# 10. 实验最终决策

根据 A/B 实验结果，确定以下原则：

1. LLM 负责理解用户目标和生成候选方案。

2. Research 负责验证会改变方案的现实变量。

3. Search 不是规划核心能力，而是 Reality Layer 的一个数据来源。

4. 不允许采用“自由搜索直到满意”的 Agent 模式。

5. 后续优化重点从 Search Agent 转向 Decision Gap Analyzer 和 Research Router。
