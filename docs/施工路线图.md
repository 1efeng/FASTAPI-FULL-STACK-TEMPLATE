# 4. Step 1 — StreamResumeStore correctness hardening（lease fencing）

**进度：✅ 完成（2026-08-13）**

## 已修实现与剩余 correctness Gate（P0-1）

基线实现曾使用 `state` key 同时承担 lease，存在旧 producer 续命/覆盖新 owner 的 split-brain 风险。当前工作区已改为：

```text
state:{request_id} 与 lease:{request_id} 分离
per-producer uuid token
Lua compare-and-renew / compare-and-release
lease lost / heartbeat exception → producer fenced
terminal write 前再次校验 token ownership
```

实现进一步收敛为 Lua 原子 claim 与原子 fenced state transition，并处理 takeover 时新旧 Pub/Sub handler 短暂并存的 race：旧 handler 在 ACK/replay 前必须验证 token ownership。heartbeat 丢失与阻塞 producer 的 `anext()` 显式竞争，lease lost 会立即关闭旧 source 并解除旧订阅者等待。

## 目标

把 state 与 lease 分离，引入 producer fencing token，使"旧 producer 被 fenced 后不得继续 publish / 不得写 terminal state"。

## 输出（实现改动，属 infra 内部）

```text
backend/app/infra/stream_resume/redis_store.py   ← lease:{request_id} 与 state:{request_id} 分离
backend/app/infra/stream_resume/runtime.py       ← heartbeat 改 Lua compare-and-renew
backend/tests/infra/stream_resume/*              ← fencing 相关测试
```

设计要点（架构 SOT 未冻结，本次补全）：

```text
state:{request_id}          → ACTIVE / DONE / FAILED / INTERRUPTED
lease:{request_id}          → <producer_token>

producer_token 生成与存储：
  token = uuid4().hex（每次 claim 生成一个新的 per-producer token）
  token 保存在 producer 进程内存（ResumableStreamRuntime 实例字段）
  不写回 state key（state 只存 transport 状态，不含 token）

claim:  SET lease:{request_id} <token> NX EX ttl
heartbeat（Lua compare-and-renew）:
    if GET lease == token: EXPIRE lease
    else: lease lost（stop publishing）
terminal transition:
    只有仍持有 token 才允许写 state
    失去 lease → fenced → 不再 publish / 不得覆盖新 owner
```

## 验收 checklist（Definition of Done）

```text
✅ lease 与 state 分离（不再用 state key 兼 lease）
✅ claim 使用 producer_token（SET lease NX EX ttl）
✅ heartbeat 用 Lua compare-and-renew（GET lease == token 才 EXPIRE）
✅ compare-and-release 不删除新 owner lease
✅ memory backend：lease 丢失/heartbeat exception 后旧 producer 被 fencing
✅ 真实 Redis 跨 context / 跨副本 subscriber attach
✅ 真实 Redis 并发 claim 只有一个 producer
✅ terminal state retention 阻止同一 stream_id 重启
✅ TTL 到期后新 producer 可 claim；旧 handler 不响应新 attach
✅ 旧 producer 不得删除新 lease、不得覆盖新 owner state
✅ heartbeat failure 会立即中断阻塞 producer，不泄漏等待中的 subscriber
✅ graceful close 释放 producer/PubSub，transport 进入 INTERRUPTED
✅ store.close() 后共享 Redis client 仍可用
```

# 5. Step 2 — AgentExecutor authoritative-history contract

**进度：✅ 完成（2026-08-13）**

## 目标

把 thin `execute(...)` 升级为携带服务端权威历史的请求 DTO，并**明确 history 排除当前 user message**（P0-4）。

## 输出

```text
backend/app/agent/executor.py      ← AgentMessage / AgentExecutionRequest / AgentExecutionResult
backend/app/modules/chat/service.py  ← history projection
backend/tests/*                    ← FakeExecutor 覆盖新契约
```

目标 contract：

```python
@dataclass(frozen=True, slots=True)
class AgentMessage:
    role: Literal["user", "assistant"]
    content: str

@dataclass(frozen=True, slots=True)
class AgentExecutionRequest:
    request_id: UUID
    conversation_id: UUID
    message: str                        # 当前 user input
    history: tuple[AgentMessage, ...]   # 当前 request 之前的 durable history
    deadline_at: datetime

@dataclass(frozen=True, slots=True)
class AgentExecutionResult:
    content: str

class AgentExecutor(Protocol):
    async def execute(self, request: AgentExecutionRequest) -> AgentExecutionResult: ...
```

## history 与 message 的边界（P0-4，硬规则）

Product lifecycle 是"先 INSERT 当前 user message + COMMIT，再执行 Agent"。因此 projection 必须排除当前消息：

```text
history = 当前 request 之前的 durable history
          （request_id != current，或 seq < current_user_message.seq）
message = 当前 request 的 user input

第二轮正确输入：
  history:  user #1, assistant #1
  message:  user #2
```

禁止出现"当前 user message 同时进 history + message"导致重复发送。

## 权威流向（不可逆）

```text
PostgreSQL durable Messages
  → ChatService history projection（排除当前 request）
  → AgentExecutionRequest.history
  → AgentExecutor.execute
```

## 验收 checklist（Definition of Done）

```text
✅ ChatService 从 Product DB 投影 user/assistant 历史
✅ history 排除当前 request 的 user message（P0-4）
✅ repository 按 Message.seq 升序
✅ history 类型只允许 user/assistant durable message
✅ FakeExecutor / RecordingExecutor 已迁移到新 request DTO，并断言完整 history
✅ 多轮对话：第二轮 history 含第一轮 user+assistant，message 为第二轮 user（不重复）
✅ 幂等 replay 不执行 Agent；后续轮 history 不重复投影
✅ 客户端伪造 history/messages/system 字段不能进入 Agent execution
✅ 当前 framework-neutral Product tests 全绿
```
