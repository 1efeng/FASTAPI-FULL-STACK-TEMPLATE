# 3. 核心设计资产（迁移时"语义照搬、框架重写"）

## 3.1 固定规划链路（架构不变量）

```text
Main → 必要需求澄清 → travel-planning Skill
     → travel-researcher（Research Findings）
     → Main 选定最终方案
     → Budget / FX（按需）
     → Markdown Contract
     → Main Final Synthesis
```

关键约束（agent.py 反复强调，迁移时不可丢）：

```text
- 关键条件（进出城市/日期/是否跨城）未明确 → 先澄清，不读 Skill、不委派 Research、不猜路线
- 非关键偏好 → 合理假设，不把规划变问卷
- JR Pass 等经济性方案 → Research 比价后决定，不预设结论
- 普通旅行问答 ≠ 完整规划：Main 可直接调 tool，不委派 Researcher
```

## 3.2 工具分层（ownership 分离）

```text
TRAVEL_TOOLS（Researcher 持有）
  search_travel_info / get_weather / search_maps

MAIN_TOOLS = TRAVEL_TOOLS + calculate_budget + convert_currency
```

Research 工具与确定性工具分离：Researcher 只能查事实，Main 才能算账。对应 ADR-0003。

## 3.3 确定性工具（纯函数 + Decimal，非 LLM）

```python
# budget.py 核心：纯函数，Decimal 量化 0.01，args_schema 是 Pydantic model
calculate_budget_data(items) -> dict   # 不保存城市价格、不做旅行判断

# currency.py 核心：同一汇率批量换算，失败只留当地货币
convert_currency_data(from, to, amounts) -> dict
```

## 3.4 环境自适应 Provider（search.py）

```text
APP_ENV=development → DuckDuckGo（免费，不调 Tavily）
APP_ENV=test        → FakeSearch（离线）
APP_ENV=production  → Tavily primary → DuckDuckGo fallback
```

`SearchProvider` 协议（name + search()），Agent 不感知供应商。与 v8 的 LiteLLM gateway / StreamResumeStore 是同类抽象。

## 3.5 工具异常降级语义（agent_tools.py 统一模式）

```python
@tool
async def get_weather(city, forecast=False):
    try:
        return await _get_weather(city=city, forecast=forecast)
    except Exception as exc:
        return f"天气查询暂时失败：{type(exc).__name__}: {exc}"
```

工具失败返回文本进入 Agent 上下文，不打断整个计划。对应产品文档 §6.4 退化语义、v8 错误契约 §3（Partial Degradation）。

## 3.6 Markdown Contract（输出协议）

固定标题不可改、不加 emoji、每日标题 `## Day N｜主题/区域`、币种规范（当地货币为事实价，人民币仅换算参考，禁用裸 `¥`）。

## 3.7 Researcher 隔离（subagent 提示词精华）

```text
- 只返回 Research Findings（7 个固定 section）
- 不读 travel-planning Skill、不读 Markdown Contract
- 不构造带答案的搜索 Query（Anti-confirmation）
- 一个非关键事实未确认不阻塞整份 Findings
- Findings 每个价格标注币种
```

## 3.8 验收资产：9 个 trajectory eval case

`evals/delegation_cases.md` 是宝贵的验收基准，精确到工具调用顺序断言：

```text
Case 1 闲聊          → 不读 Skill、不调 Researcher、不调 Tool
Case 2 普通事实       → Main 直接调 get_weather
Case 3 信息不足规划    → 先澄清，不委派 Researcher
Case 4 完整跨城规划    → 完整链路（Skill→Researcher→Findings→Budget→FX→Contract→Final）
Case 5 JR Pass        → Research 前不预设结论
Case 6 预算一致性      → 只汇总采用方案，不混备选价
Case 7 币种           → 无裸 ¥，人民币来自 convert_currency
Case 8 模型切换        → 改 LLM_PROVIDER 不改 Agent/Tool 代码
Case 9 搜索环境        → dev/test/prod 三态策略
```

# 5. 借鉴纪律（对齐 v8.2 架构 SOT，不可违反）

1. **不要现在写 tool**：AGENTS.md 禁止"顺手提前做 Travel Tool"。当前施工位是 Step 2（AgentExecutor history contract），Travel Domain 在 Generic Chat Production Gate 之后。

2. **确定性工具保持纯函数**：budget/currency 的 Decimal 纯函数设计是 ADR-0003 的完美实现，迁移时不要改成 LLM 判断。

3. **工具退化语义不能丢**：`try/except → 返回文本失败结果` 模式对应 v8 错误契约 §3，每个 tool 迁移时都要保留。

4. **Researcher 隔离不能破**：Research 中间 Tool Result 留 Researcher Context，Main 只收 Findings——这对应 v8 架构 SOT 的 "Agent implementation 不得反向查 Product repository" 同款 ownership 纪律。

5. **Provider 抽象一致**：v6 的 SearchProvider 协议、v8 的 StreamResumeStore/LiteLLM gateway，都是"依赖 contract 不依赖具体实现"的同一原则。迁移搜索时保持这个抽象，不要在 tool 里硬编码供应商。

6. **框架重写，语义照搬**：v6 是 Deep Agents + LangGraph，v8 是 PydanticAI + Harness。所有 `create_deep_agent` / `task()` / `subagent_type` 语法都要重写，但 SKILL.md 的方法论、Markdown Contract 的规范、工具的 schema 和退化语义是稳定的业务资产，直接搬。
