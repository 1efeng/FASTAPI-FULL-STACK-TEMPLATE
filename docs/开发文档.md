# 2. Vibe Coding 的基本协议

每次任务遵循：

```text
Read
 ↓
Understand actual code
 ↓
Identify owner
 ↓
Change minimum scope
 ↓
Unit / Integration
 ↓
Eval（涉及 Agent 行为时）
 ↓
Update docs
 ↓
Commit intentionally
```

禁止：

```text
看到需求就直接写代码
根据聊天记忆猜仓库现状
为“完整”顺手加未来功能
发现框架有能力仍自研一套
改 Prompt 不跑 Eval
改依赖不更新 lock
只验证 happy path
```

# 5. Framework Ownership — 开发最重要规则

开发前先判断“这是谁的能力”。

| 能力 | Owner | Travel Agent 应做什么 |
|---|---|---|
| Agent Harness | Deep Agents | 配置业务 Agent |
| Context Isolation / Offloading / Summarization | Deep Agents | 定义业务关键上下文 |
| Checkpoint / Resume | LangGraph | 接 AsyncPostgresSaver |
| LLM Gateway | LiteLLM Proxy | 接 OpenAI-compatible client |
| LLM Retry / Fallback / Health | LiteLLM | 配 model group / policy |
| LLM Spend | LiteLLM | 做业务 cost attribution |
| AI Trace | LangSmith | 绑定业务 metadata |
| AI Eval | LangSmith / AgentEvals | 定义 dataset / pass criteria |
| Infrastructure spans / propagation | OpenTelemetry instrumentation | 创建/传播基础设施 span，不建设独立 tracing platform |
| HTTP / SSE | FastAPI | 定义业务 endpoint / event |
| Business Durable State | PostgreSQL | 建业务 schema |
| Rate / Quota / Locks | Redis | 实现业务策略 |
| Travel Product Logic | Travel Agent | 自己实现 |

如果一个 PR 准备新增：

```text
CircuitBreaker.py
CheckpointRepository.py
ConversationSummarizer.py
EvalDashboard.py
SSEEncoder.py
TraceIdManager.py
LLMCostCalculator.py
```

必须先停止，重新确认框架 Owner。

# 6. 禁止重复造轮子清单

默认禁止自研：

```text
❌ LLM Gateway
❌ Provider routing engine
❌ Provider health engine
❌ CLOSED / OPEN / HALF_OPEN model breaker
❌ LLM spend pricing engine
❌ LangGraph checkpoint schema
❌ generic context summarization engine
❌ Eval platform / experiment dashboard
❌ SSE wire encoder / ping manager
❌ custom distributed trace-id system
❌ regex-only universal PII framework
```

允许自研的是**业务 Policy**：

```text

✅ Resource authorization
✅ Idempotency
✅ Request lifecycle
✅ Research trust
✅ Business cost attribution
✅ Product errors
✅ Domain-specific Tool degradation
```

# 7. Dependency Governance

## 7.1 `uv.lock` 是 exact version Source of Truth

`pyproject.toml` 表达兼容范围；`uv.lock` 决定实际生产依赖。

生产 / CI 使用：

```bash
uv sync --frozen
```

或等价 locked 模式。

禁止生产构建临时升级依赖。

## 7.2 Framework 文档版本必须与锁定版本匹配

特别注意：

- Deep Agents 仍处于快速演进阶段；
- 最新 Context Summarization 行为可能要求更高版本；
- FastAPI Native SSE 需要 FastAPI 0.135.0+；
- LiteLLM Proxy 生产镜像必须 pin tested version / digest。

所以不能：

```text
打开最新官方文档
→ 直接复制 API
→ 不看 uv.lock
```

## 7.3 Dependency Upgrade 流程

```text
create upgrade branch
 ↓
update dependency
 ↓
update uv.lock
 ↓
unit tests
 ↓
integration tests
 ↓
CLI smoke
 ↓
Basic Eval
 ↓
review breaking changes
 ↓
gray
```

涉及 Deep Agents / LangGraph / LangChain / LiteLLM 的升级，必须记录在 PR 和实现快照中。

# 9. LiteLLM 开发规则

## 9.1 Owner

LiteLLM 负责：

```text
retry
fallback
provider routing
health check
cooldown
timeout
RPM / TPM
max parallel
Virtual Key
budget
spend
actual model metadata
```

## 9.2 禁止多层 Retry

必须检查：

```text
Provider SDK max_retries
LangChain middleware retry
LiteLLM retry
```

只允许 LiteLLM 成为 LLM retry/fallback 主 Owner。

## 9.3 Request Deadline 不属于 LiteLLM

FastAPI/Application 持有 end-to-end deadline。

每次调用 LiteLLM 时使用剩余预算控制 timeout。

## 9.4 Model Group 命名

P0：

```text
travel-agent
```

P1 再：

```text
travel-main
travel-research
```

不要把具体 Provider 名写进 Agent prompt。

# 10. LangGraph Persistence 开发规则

生产使用：

```python
AsyncPostgresSaver
```

禁止业务 ORM 自己创建：

```text
checkpoints
checkpoint_writes
thread_state
```

这些属于 LangGraph implementation detail。

Agent execution 期间 checkpoint 写入独立于业务 transaction。

业务完成状态只由：

```text
messages
request_runs
```

控制。

# 11. Conversation 与 Business Persistence

业务建议实体：

```text
users
conversations
messages

```

`thread_id` 建议由服务端生成 / 映射，不允许客户端随意把一个 thread_id 当授权凭证。

第一阶段计划继续保存在 assistant message Markdown 中，不创建复杂 Plan aggregate。

# 12. Context Engineering 开发规则

## 12.1 先使用 Deep Agents 内置机制

优先：

```text
context isolation
filesystem offloading
automatic summarization
ContextOverflow recovery
```

前提：锁定版本已确认支持且通过 Eval。

## 12.2 不建双 Summary Source of Truth

禁止同时：

```text
Deep Agents summary
+
conversation.context_summary
```

除非第二者是明确业务实体，而不是纯粹为 context compression 服务。

## 12.3 Business-critical context

要明确哪些语义不能在压缩中丢：

```text
最新完整旅行计划
用户明确硬约束
关键日期
进出城市
旅行者限制
预算硬上限
最新未完成请求意图
```

通过 Eval 验证长会话行为。

# 13. Runtime Guard 开发规则

保留：

```text
LangGraph recursion_limit
```

新增时优先复用官方：

```text
ModelCallLimitMiddleware
ToolCallLimitMiddleware
```

不要用一个巨大的 recursion_limit 代替所有成本保护。

Main 和 custom Researcher 所需 Middleware 必须分别显式安装，不假设自动继承。

# 14. Tool 开发规则

Tool 必须：

- schema 清晰；
- 不隐藏新的 LLM；
- 参数确定；
- timeout；
- cancellation；
- error taxonomy；
- 能降级时返回标准降级；
- 动态事实带 source / fetched_at（能力允许时）。

Research Tool 和 deterministic Tool 分开。

```text
Research Tools
→ search / maps / weather

Deterministic Tools
→ budget / currency
```

Budget 不查价格；Research 不做数学总和。

# 15. FastAPI 开发规则

正式 API 采用 async 路径。

第一版建议：

```text

GET  /v1/conversations

DELETE /v1/conversations/{id}
GET  /health/live
GET  /health/ready
```

## Native SSE

锁定版本支持时使用：

```python
from fastapi.sse import EventSourceResponse, ServerSentEvent
```

不要自己编码：

```text
text/event-stream
ping timer
Cache-Control
X-Accel-Buffering
```

业务只定义：

```text
status
message_delta
final
error
```

# 16. Request Lifecycle 实现规则

单次请求建议：

```text
Auth
 ↓
Authorization
 ↓
Rate / Quota / Concurrent Limit
 ↓
Idempotency
 ↓
request_id + OTel root span
 ↓
Persist user message + request_run(in_progress)
 ↓
Agent
 ↓
Persist assistant final + request_run(completed)
 ↓
COMMIT
 ↓
SSE final
```

## End-to-End Deadline

在 Request Context 中保存：

```text
started_at
deadline_at
```

调用任何模型 / Tool 时都检查剩余时间。

不要让 LiteLLM 的 per-call timeout 代替用户请求总 Deadline。

## Cancellation

客户端断开后：

- 取消可取消的 model / tool task；
- 更新 request status；
- 不把已完成 durable result 删除。

---

# 17. Idempotency 实现规则

Key 维度至少：

```text
user_id + idempotency_key
```

状态：

```text
running
completed
failed
cancelled
```

行为：

```text
running → 返回已有 request_id
completed → 返回已有结果
```

是否允许 failed key 重试必须在 API Contract 中明确，不允许每个 endpoint 自己决定。

---

# 18. Auth / Authorization

不能只做 JWT。

每个资源访问都需要 ownership check：

```text
conversation.user_id == current_user.id
request_run.user_id == current_user.id
```

客户端传入：

```text
user_id
thread_id
conversation_id
request_id
```

都不是可信身份依据。

---

# 19. Redis 使用边界

Redis 用于：

```text
user rate limit
IP rate limit
daily AI quota
concurrent requests
distributed lock
short-lived request coordination
```

不用于作为主要 durable conversation 数据库。

LiteLLM 也可以使用同一 Redis Server，但应使用独立 key namespace / logical ownership。

---

# 20. PostgreSQL 使用边界

推荐逻辑隔离：

```text
postgres server
│
├── travel_agent database/schema
│   └── business ORM migrations
│
├── langgraph persistence area
│   └── AsyncPostgresSaver owner
│
└── litellm database/schema
    └── LiteLLM migrations
```

不要让三套 migration tool 同时修改同一 schema namespace。

生产必须：

```text
migration
indexes
backup
retention
restore procedure
restore drill
```

# 22. Observability 开发规则

## OTel

FastAPI 建 root span；所有跨层 correlation 优先用 OTel。

不要：

```python
trace_id = uuid.uuid4()
```

自己实现 distributed tracing。

## LangSmith

用于：

```text
Agent Trace
Tool trajectory
Dataset
Evaluation
Experiment
```

## LiteLLM

用于：

```text
model call id
actual provider / deployment
retry / fallback
health / cooldown
cost
```

## Structured Log

普通日志必须带：

```text
request_id
trace_id
user hash / safe identity
service
level
error_code
```

禁止普通日志写：

```text
API Key
JWT
完整 Secret
未治理的 Passport / PII
```

# 23. PII / Security Middleware

Agent 输入 / 输出 / Tool Result 的 PII 优先评估 LangChain `PIIMiddleware`：

```text
redact
mask
hash
block
```

但不能误认为它自动解决：

```text
API logs
DB retention
backup
LangSmith policy
LiteLLM logging policy
```

这些仍由平台治理。

# 24. Research Security

网页内容永远视为：

```text
UNTRUSTED DATA
```

Researcher 只能从中提取旅行事实。

禁止网页：

- 覆盖 system prompt；
- 要求暴露 secret；
- 要求修改 Agent policy；
- 要求调用未授权 Tool；
- 把“网页里的指令”当开发者指令。

# 34. 当前禁止的典型 Vibe Coding 行为

```text
“为了稳一点，我再写一个 CircuitBreaker”
→ 禁止，LiteLLM Owner

“为了跨会话，我自己建 checkpoint 表”
→ 禁止，LangGraph Owner

“为了长会话，我建 context_summary 字段并自动摘要”
→ 先检查 Deep Agents，不重复做通用 compaction

“为了 Eval，我做一个后台页面”
→ 禁止，优先 LangSmith

“为了 SSE，我手写 event-stream 编码器”
→ 禁止，FastAPI Native SSE

“为了 trace，我生成 UUID 并到处传”
→ 禁止，OpenTelemetry

“LiteLLM 已经算 cost，但我再做模型价格表”
→ 默认禁止，只做 business attribution
```

---

# 35. 最终开发原则

> **Vibe Coding 不是减少工程约束，而是让 AI 在明确的 Owner、Contract、Tests、Eval、Version Lock 和 Production Boundary 里快速工作。**

代码越少不代表能力越少；如果成熟框架已经稳定解决问题，正确的工程选择就是**配置、集成、验证，而不是重写**。
