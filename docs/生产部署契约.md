# Travel Agent v8.2 生产部署契约

> 更新时间：2026-08-13  
> 目标：从模块化单体平滑演进到多实例；不以 sticky session 作为 streaming correctness 前提。

# 1. Stage A — 模块化单体

```text
Reverse Proxy
  ↓
FastAPI container/process
├ Product Runtime
├ ExecutionSupervisor        # M8 target
├ AgentExecutor/PydanticAI
├ StreamResumeStore runtime
└ Redis Pub/Sub subscriber

PostgreSQL
Redis
LiteLLM
```

# 2. Stage B — 多 FastAPI Replicas

```text
Load Balancer
├ FastAPI A  ← may own Agent execution
├ FastAPI B  ← may own reconnect subscriber
└ FastAPI C

Shared PostgreSQL
Shared Redis
Shared LiteLLM
```

reconnect：

```text
subscriber B
→ Redis Pub/Sub resume request
→ producer A
→ backlog + live chunks
→ B → browser
```

因此：

```text
sticky session = 可选优化
不是 correctness requirement
```

# 3. Redis

Travel Agent 与 LiteLLM 可共享 Redis service，但：

```text
prefix / ACL / connection pool ownership 清晰
```

Travel Agent：

```text
Product coordination
+ StreamResumeStore KV/PubSub
```

M8 默认不要求 Redis Streams / Consumer Group。

# 4. Process Crash Boundary

当前 M8：

```text
producer task 在 FastAPI process 内
```

所以：

```text
browser F5                     ✅
subscriber 切换 replica        ✅
producer process hard crash    ❌ execution resume
server restart                 ❌ execution resume
```

hard crash 后：

```text
RequestRun 必须 stale-running reconcile
```

不得宣称 StreamResumeStore 等于 DBOS。

# 5. Graceful Shutdown

必须：

```text
stop accepting new executions
bounded drain/cancel active execution according to policy
transport state 不假装 DONE
StreamResumeStore close
shared Redis client 最后由 app infra close
RequestRun reconcile
```

禁止：

```text
deploy interruption → Product completed
```

# 6. Streaming Proxy

Reverse proxy/LB 必须验证：

```text
SSE buffering disabled/compatible
idle timeout
max connection duration
keepalive
HTTP/2 behavior
client disconnect propagation only to subscriber
```

不能让 proxy disconnect 自动触发 Product cancel。

# 7. PostgreSQL

Business SOT：

```text
Conversation
Message
RequestRun
Usage
```

backup/restore 必须覆盖 Business DB。

至少一次真实 restore drill。

# 8. LiteLLM

独立 service：

```text
pinned image
health/readiness
provider credentials
fallback/routing
```

与 Product API 可独立扩缩。

# 9. Health

FastAPI：

```text
/health/live
/health/ready
```

readiness 应考虑：

```text
DB
Redis
关键依赖初始化
```

是否把 LiteLLM failure 纳入 hard readiness 根据降级策略决定，不能造成无意义全站摘除。

# 10. Observability

至少：

```text
structured logs
request_id
trace_id
OpenTelemetry
Product lifecycle metrics
Redis resume metrics
active executions
active subscribers
reconnect failures
stale-running count
LiteLLM metrics
alerts
```

# 11. Capacity

压测：

```text
HTTP RPS
active SSE
execution concurrency
F5/reconnect burst
Redis Pub/Sub
DB pool
LiteLLM/provider quota
tool latency
```

10,000 DAU 不直接等于固定 QPS。

# 12. Future Durable Execution

真实出现：

```text
restart-loss
长任务
worker handoff
独立 execution scaling
```

再引入：

```text
DBOS / Temporal
```

演进时 Product contract 尽量保持：

```text
RequestRun
AgentExecutionRequest
AgentExecutor
StreamResumeStore
```

不整体推倒。

# 13. P0 不强制

```text
Kubernetes
Kafka
Redis Cluster
Consumer Group
Service Mesh
Postgres sharding
Agent microservice
```
