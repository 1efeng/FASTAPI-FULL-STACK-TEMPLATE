---

# 2. CURRENT 与 TARGET 分离

```text
当前代码 + 测试
→ CURRENT implementation reality

产品文档
→ Product intent

已接受的架构文档
→ TARGET architecture
```

当前代码存在某个框架、Agent、数据库或网关，不代表它自动成为新 TARGET。

同样，新产品/架构文档尚未形成明确迁移任务前，也不允许为了“从 0”而随意重写当前代码。

---

# 3. Archive 规则

`docs/archive/**` 只回答：

```text
以前设计过什么？
为什么曾经这么设计？
某次 benchmark / incident 当时说明了什么？
```

它不能回答：

```text
现在应该怎么设计？
Cursor 下一步应该实现什么？
当前架构 ownership 是什么？
```

旧文档中的决定只有在新 Product / Architecture 推导中重新采纳后才恢复决策权。

---

# 4. Reset 后专项契约

新的专项契约不自动继承旧契约正文。

只有当某个 domain 在新 Architecture Baseline 下重新确认后，才重新建立对应 Active Contract，例如：

```text
接口契约
数据契约
安全契约
部署契约
可观测性契约
```

在此之前，旧契约只用于回答：

```text
CURRENT 代码过去按什么约束实现？
有哪些生产要求曾经存在？
迁移时可能有哪些兼容成本？
```

不能用于回答新的 TARGET 应该是什么。

---

# 5. Reset 后 ADR 规则

2026-08-19 之前的 ADR 只做历史记录。

新的核心架构决定必须新建 reset 后 ADR，至少写清：

```text
Product requirement
Observed constraint
Options
Decision
Rejected alternatives
Validation
Migration impact
```
