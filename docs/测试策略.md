# 测试策略

# 1. Test Layers

```text
Unit
Integration
E2E
AI Eval
Failure Injection
Load / Capacity
```

# 2. Unit

覆盖：

- budget；
- currency；
- error mapping；
- idempotency state machine；
- authorization ownership；
- deadline remaining-time calculation；
- Tool degradation decision。

# 3. Integration

覆盖：

- PostgreSQL business repositories；
- Redis quota/rate；
- LangGraph checkpointer；
- LiteLLM adapter；
- FastAPI Agent Streaming Adapter（锁定版本官方协议）；
- OTel propagation；
- LangSmith integration smoke（可分环境）。

# 4. E2E

至少：

```text
create conversation
→ send chat stream
→ status
→ final
→ reload conversation
→ modify plan
```

# 5. Failure

必须人为测试：

- LiteLLM primary failure；
- LiteLLM all models failure；
- Search failure；
- Weather failure；
- Maps failure；
- DB failure；
- Redis failure；
- SSE client disconnect；
- deadline exceeded；
- runtime call limits；
- duplicate request。

# 6. Persistence Ordering

验证：

```text
如果 SSE final 被发送
→ assistant final 必须已经在 Business DB
```

但不要假设 LangGraph checkpoint 与 business transaction 是同一 transaction。

# 7. Idempotency

并发发送相同 key：

- 最多一个昂贵 Agent execution；
- 其他请求得到 existing request/result。

# 8. Load Test

拆层：

## API/SSE layer

使用 mock agent / fake gateway 压连接和 request lifecycle。

## DB/Redis

压实际 pool / lock / quota path。

## LiteLLM

单独压 Gateway routing / concurrency / telemetry。

## Real Model

只用受控样本验证真实 provider quota/latency，不用真实高价 LLM 做全量压力流量。

# 9. Capacity

10,000 DAU 不能直接换算 QPS。

压测参数来自产品预估 + 灰度数据：

- peak RPS；
- SSE duration；
- model calls/request；
- tool calls/request；
- token distribution。

# 10. CI / Release

PR：

- unit；
- selected integration。

main/release：

- integration；
- Basic Eval；
- migration check；
- security check；
- smoke。

重大 infra upgrade 再跑对应 load/failure tests。
