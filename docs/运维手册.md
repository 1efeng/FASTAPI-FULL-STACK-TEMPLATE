# 生产运维手册

# 1. Incident Priority

## Sev-0 / Critical

- cross-user data exposure；
- widespread final data loss；
- all production traffic unavailable；
- secret compromise。

## Sev-1

- major model/provider outage with no fallback；
- DB unavailable；
- Redis outage causing request-control failure；
- severe cost runaway。

# 2. LiteLLM / Provider Incident

检查：

1. LiteLLM replicas health；
2. fallback rate；
3. cooldown/unhealthy deployment；
4. 429 / 5xx；
5. provider quota；
6. Redis / Postgres dependency；
7. recent config/image change。

不要第一反应在 Application 再开一层 retry。

# 3. All Models Unavailable

- confirm Gateway;
- confirm providers;
- return `MODEL_UNAVAILABLE`;
- avoid static fabricated travel facts;
- communicate outage;
- rollback recent gateway config if relevant.

# 4. Cost Spike

检查：

- request volume；
- idempotency miss；
- model-call runaway；
- Tool/Agent loop；
- fallback；
- model routing；
- abusive user；
- LiteLLM spend。

临时措施优先：

- business quota；
- concurrency；
- LiteLLM service limits；
- disable bad deployment/config。

# 5. PostgreSQL

区分：

- business DB；
- LangGraph domain；
- LiteLLM domain。

故障时先确认哪个 domain 失败，不要一概认为全部服务都不可用。

Business DB 无法 durable final 时，不得发送 final。

# 6. Redis

影响：

- business rate/quota/concurrency；
- LiteLLM shared routing/limit state（取决于配置）。

如果 quota 无法安全核实时，采用 `安全与数据治理.md` 规定的 fail-open/fail-closed 策略，不能现场拍脑袋。

# 7. Tool Provider

按 degradation matrix：

- Weather fail；
- Maps fail；
- Search fail；
- FX fail。

Critical Research 无法核实时停止伪造当前事实。

# 8. LangGraph Persistence

检查：

- checkpointer connection；
- setup/migration；
- thread id；
- pending writes；
- DB pool。

不要直接手改内部 checkpoint tables 作为常规修复。

# 9. LangSmith / OTel

Observability outage 原则上不阻断主业务，但必须保留 platform alert / log。

# 10. Bad Release

- stop rollout；
- compare commit / `uv.lock` / images / LiteLLM config；
- rollback；
- run smoke；
- run Basic Eval；
- record incident。

# 11. Security Incident

Cross-user access：

1. immediately restrict endpoint;
2. preserve audit evidence;
3. identify scope;
4. rotate affected secrets if any;
5. patch ownership query;
6. security retest;
7. follow notification/compliance procedure if applicable.

# 12. Incident Record

至少记录：

```text
time
request/trace examples
impact
root cause
framework/component owner
mitigation
permanent fix
tests/evals added
```
