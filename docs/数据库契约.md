# 5. request_run

一次昂贵 Product Agent 请求。

```text
id                    UUID PK == request_id
user_id               UUID NOT NULL
conversation_id       UUID NOT NULL
idempotency_key       VARCHAR(255) NOT NULL
status                running|completed|failed|cancelled
started_at            TIMESTAMPTZ NOT NULL
deadline_at           TIMESTAMPTZ NOT NULL
finished_at           TIMESTAMPTZ NULL
error_code            VARCHAR(64) NULL
created_at
updated_at
```

核心唯一约束：

```text
UNIQUE(user_id, idempotency_key)
```

P0 状态机：

```text
running
 ├ completed
 ├ failed
 └ cancelled
```

终态竞争必须：

```sql
UPDATE request_run
SET status = :terminal,
    finished_at = :now,
    error_code = :error
WHERE id = :request_id
  AND status = 'running';
```

只有更新 1 行的一方获得 terminal ownership。

---

# 6. cancelled 语义

`cancelled` 表示：

```text
Product cancel CAS 赢得 terminal race
→ no later Agent final is commit-eligible
```

它不表示：

```text
底层 coroutine 在 CAS 同一时刻已经物理停止
```

因此 late final：

```text
cancelled already durable
→ success CAS / success transaction must fail
→ DROP final
```

# 9. Product Write Lifecycle

## Start TX

Agent 前必须：

```text
BEGIN
owned active conversation check
INSERT request_run running
INSERT user message
UPDATE last_message_at
COMMIT
```

只有 COMMIT 成功才允许执行 Agent。

## Success TX

```text
BEGIN
INSERT assistant final
UPDATE request_run running → completed
assert exactly 1 row
UPDATE last_message_at
COMMIT
```

Product success：

```text
assistant durable + RequestRun completed + COMMIT
```

不是模型最后 token。

## Failed

```text
running → failed
error_code = Product Error Code
finished_at = now
```

不插入伪 assistant message。

## Cancelled

```text
running → cancelled CAS
```

不保存 partial assistant 为 Product Message。


这些状态：

```text

```

这些全部是 ephemeral infrastructure state。

# 11. Reconciliation

任何以下情况：

```text
stream missing
terminal event lost
producer crash
Redis resume failure
browser refresh
```

Product truth 都回：

```text
request_run
+
message
```

如果：

```text
RequestRun = completed
```

必须存在 durable assistant final；否则视为 Product invariant failure。

---

# 12. Stale Running

M8 execution 不是 crash-durable。

如果 producer process hard crash：

```text
request_run 可能仍 running
```

必须有 recovery/reconciliation：

```text
deadline_at < now
+
status = running
→ mark failed/expired according to Product policy
```

不要通过 StreamState 自动决定 Product terminal。

---

# 13. Business Usage（M7）

`business_llm_usage` 归 Product domain，用：

```text
request_id
user_id
conversation_id
logical_model
provider/model metadata（Product-safe）
input/output tokens
cost
created_at
```

LiteLLM 内部 spend/telemetry 不替代 Product billing ledger。

字段来源必须可审计：

```text
Product lifecycle
→ request_id / user_id / conversation_id / agent_role

AgentExecutor token snapshot
→ call_index / logical_model / reported_model / provider_response_id
→ input/output/cache/audio tokens（unknown 保持 NULL，不写 0）

LiteLLM evidence
→ litellm_call_id / actual model or deployment / authoritative cost / status
```

`provider_response_id != litellm_call_id`，`reported_model != guaranteed actual deployment`。PydanticAI framework price estimate 不进入 authoritative `cost`。写表前还必须补齐失败/cancel/deadline attempt 与 Subagent 的 recorder/reconciliation 设计；当前 success-result snapshot 不是完整 billing ledger。

# 14. Regenerate / Branch

M9 第一版不要默认实现 completed answer regenerate。

原因：

```text
当前 Message 模型 = 每 RequestRun 一个 user + 0/1 assistant
```

naive regenerate 会重复 user message 并污染线性 history。

真正 regenerate/edit/branch：

```text
需要 message lineage / branch contract
```

以后单独设计，不提前加 `parent_message_id`。
